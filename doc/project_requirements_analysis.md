# 1. 서론

## 1.1 목적 및 범위

이 문서는 사용자가 웹 환경에서 개인 파일을 업로드, 다운로드, 관리할 수 있는 미니드라이브 시스템의 요구사항을 조사하고 정의하는 문서이다.  
미니드라이브는 사용자가 로그인 후 파일을 저장하고, 저장된 파일을 조회하거나 다운로드하며, 필요하지 않은 파일을 삭제할 수 있도록 지원하는 웹 기반 파일 관리 시스템이다.

본 문서는 미니드라이브 시스템에서 필요한 기능적 요구사항, 비기능적 요구사항, 인터페이스 요구사항, 제약사항을 정의한다. 또한 시스템의 주요 사용자와 기능 흐름을 분석하여 향후 설계 및 구현 단계에서 기준 문서로 활용하는 것을 목적으로 한다.

본 문서의 범위는 다음과 같다.

- 사용자 회원가입 및 로그인 기능
- 파일 업로드 기능
- 파일 목록 조회 기능
- 파일 다운로드 기능
- 파일 삭제 기능
- 폴더 생성 및 파일 분류 기능
- 파일 검색 기능
- 사용자 저장 공간 관리 기능
- 관리자 사용자 관리 기능
- 시스템 보안 및 데이터 관리 기능

# 2. 시스템 개요

## 2.1 소프트웨어 컨텍스트

미니드라이브 시스템은 사용자가 웹 브라우저를 통해 접근하는 파일 저장 및 관리 서비스이다.  
사용자는 회원가입과 로그인을 통해 본인의 계정에 접근하고, 파일 업로드, 다운로드, 삭제, 검색, 폴더 관리 기능을 사용할 수 있다.  
관리자는 사용자 계정 및 시스템 저장소 상태를 관리하며, 비정상적인 파일 사용이나 저장 공간 초과 등의 상황을 확인할 수 있다.

## 2.1.1 Actor Table

| Actor | Role |
|---|---|
| 사용자 | 미니드라이브에 가입하여 파일을 업로드, 다운로드, 조회, 삭제하는 일반 이용자 |
| 관리자 | 사용자 계정과 시스템 저장소 상태를 관리하는 운영자 |
| 시스템 | 사용자 요청을 처리하고 파일 및 계정 정보를 저장, 조회, 삭제하는 소프트웨어 시스템 |
| 파일 저장소 | 사용자가 업로드한 파일이 실제로 저장되는 서버 저장 공간 |
| 데이터베이스 | 사용자 정보, 파일 정보, 폴더 정보, 저장 용량 정보를 저장하는 시스템 |

본 문서에서는 Use Case Diagram을 텍스트 형태로 표현한다.

  - 로그인을 한다.

  - 파일 목록을 조회한다.
  - 파일을 다운로드한다.
  - 파일을 삭제한다.
  - 폴더를 생성한다.
  - 파일을 검색한다.
  - 저장 용량을 확인한다.

- 관리자
  - 로그인을 한다.
  - 사용자 계정을 관리한다.
  - 시스템 저장소 상태를 확인한다.

- 시스템
  - 사용자 정보를 저장한다.
  - 로그인 정보를 검증한다.
  - 파일 정보를 저장한다.
  - 파일 목록을 제공한다.
  - 파일 다운로드를 처리한다.
  - 파일 삭제를 처리한다.
  - 저장 용량을 계산한다.

### Stakeholders and Interests

- 사용자 : 자신의 계정을 생성하여 미니드라이브 서비스를 이용하기를 원한다.
- 시스템 : 입력된 회원 정보를 검증하고 사용자 정보를 안전하게 저장한다.

### Trigger

사용자는 회원가입 버튼을 누른다.

### Relationships

- Association : 사용자
- Include : 사용자 정보 저장
- Extend :
- Generalization :

### Normal Flow of Events

1. 사용자는 회원가입 화면으로 이동한다.
2. 사용자는 아이디, 비밀번호, 이름, 이메일 주소를 입력한다.
3. 사용자는 회원가입 버튼을 누른다.
4. 시스템은 입력값의 공란 여부를 확인한다.
5. 시스템은 아이디와 이메일의 중복 여부를 확인한다.
6. 시스템은 비밀번호를 해시 처리하여 저장한다.
7. 시스템은 회원가입 성공 메시지를 출력한다.
8. 시스템은 로그인 화면으로 이동한다.

### Subflows

- S-1 : 회원가입 성공
  1. 시스템은 사용자 정보를 DB에 저장한다.
  2. 시스템은 회원가입 완료 메시지를 출력한다.

### Alternate / Exceptional Flows

- 4.a1 : 필수 입력값에 공란이 있을 경우 시스템은 회원가입 실패 이유를 화면에 출력한다.
- 5.a1 : 이미 사용 중인 아이디가 있을 경우 시스템은 중복된 아이디라는 메시지를 출력한다.
- 5.a2 : 이미 사용 중인 이메일이 있을 경우 시스템은 중복된 이메일이라는 메시지를 출력한다.
- 6.a1 : 비밀번호 저장 중 오류가 발생하면 시스템은 회원가입 실패 메시지를 출력한다.

  1. 시스템은 로그인 실패 이유를 화면에 출력한다.

- 4.a1 : 존재하지 않는 아이디이면 시스템은 로그인 실패 메시지를 출력한다.
- 4.a2 : 비밀번호가 일치하지 않으면 시스템은 로그인 실패 메시지를 출력한다.

### Stakeholders and Interests

- 사용자 : 자신이 저장한 파일 목록을 확인하고 관리하기를 원한다.
- 시스템 : 사용자별 파일 정보를 조회하여 화면에 제공한다.

### Trigger

사용자는 파일 목록 화면에 접속한다.

### Relationships

- Association : 사용자
- Include : 파일 정보 조회
- Extend : 파일 검색

  2. 시스템은 파일 목록을 최신 상태로 화면에 표시한다.

## 3.1 정적 분석

미니드라이브 시스템의 주요 클래스는 사용자, 관리자, 로그인, 회원가입, 파일, 파일 DB, 폴더, 폴더 DB, 저장소, 저장 용량 관리 클래스로 구성된다.

- 폴더 정보는 폴더 DB에 저장된다.
- 실제 파일 데이터는 파일 저장소에 저장된다.

# 3.3 동적 분석

본 문서에서는 동적 분석을 시퀀스 흐름의 텍스트 형태로 표현한다.

## 3.3.1 회원가입을 한다.

1. 사용자 → 회원가입 화면 : 회원가입 요청
2. 사용자 → 시스템 : 아이디, 비밀번호, 이름, 이메일 입력
3. 시스템 → 사용자 DB : 아이디 및 이메일 중복 확인
4. 사용자 DB → 시스템 : 중복 확인 결과 반환
5. 시스템 → 사용자 DB : 사용자 정보 저장
6. 사용자 DB → 시스템 : 저장 성공 반환
7. 시스템 → 사용자 : 회원가입 성공 메시지 출력

예외 흐름

- 입력값이 공란이면 시스템은 회원가입 실패 메시지를 출력한다.
- 아이디 또는 이메일이 중복되면 시스템은 중복 오류 메시지를 출력한다.

## 3.3.2 로그인을 한다.

1. 사용자 또는 관리자 → 로그인 화면 : 로그인 요청
2. 사용자 또는 관리자 → 시스템 : 아이디, 비밀번호 입력
3. 시스템 → 사용자 DB : 로그인 정보 검증 요청
4. 사용자 DB → 시스템 : 로그인 검증 결과 반환
5. 시스템 → 사용자 또는 관리자 : 로그인 결과 출력
6. 시스템 → 사용자 또는 관리자 : 권한에 맞는 메인 화면 제공

예외 흐름

- 아이디가 존재하지 않으면 로그인 실패 메시지를 출력한다.
- 비밀번호가 일치하지 않으면 로그인 실패 메시지를 출력한다.

## 3.3.3 파일을 업로드한다.

1. 사용자 → 시스템 : 파일 업로드 요청
2. 사용자 → 시스템 : 업로드할 파일 선택
3. 시스템 → 저장 용량 관리 : 남은 용량 확인 요청
4. 저장 용량 관리 → 시스템 : 남은 용량 결과 반환
5. 시스템 → 파일 저장소 : 파일 저장 요청
6. 파일 저장소 → 시스템 : 파일 저장 성공 반환
7. 시스템 → 파일 DB : 파일 정보 저장 요청
8. 파일 DB → 시스템 : 파일 정보 저장 성공 반환
9. 시스템 → 사용자 : 업로드 성공 메시지 출력
10. 시스템 → 사용자 : 갱신된 파일 목록 출력

예외 흐름

- 파일을 선택하지 않으면 파일 선택 요청 메시지를 출력한다.
- 저장 용량이 부족하면 업로드 실패 메시지를 출력한다.
- 허용되지 않는 파일 형식이면 업로드 실패 메시지를 출력한다.

## 3.3.4 파일 목록을 조회한다.

1. 사용자 → 시스템 : 파일 목록 조회 요청
2. 시스템 → 파일 DB : 사용자 ID 기준 파일 목록 조회 요청
3. 파일 DB → 시스템 : 파일 목록 반환
4. 시스템 → 사용자 : 파일 목록 화면 출력

예외 흐름

- 저장된 파일이 없으면 “저장된 파일이 없습니다.”라는 메시지를 출력한다.
- 파일 목록 조회 중 오류가 발생하면 조회 실패 메시지를 출력한다.

## 3.3.5 파일을 다운로드한다.

1. 사용자 → 시스템 : 파일 다운로드 요청
2. 시스템 → 파일 DB : 파일 정보 조회 요청
3. 파일 DB → 시스템 : 파일 정보 반환
4. 시스템 → 파일 저장소 : 파일 존재 여부 확인
5. 파일 저장소 → 시스템 : 파일 데이터 반환
6. 시스템 → 사용자 : 파일 다운로드 제공

예외 흐름

- 파일이 존재하지 않으면 파일 없음 메시지를 출력한다.
- 접근 권한이 없는 파일이면 접근 불가 메시지를 출력한다.
- 다운로드 중 오류가 발생하면 다운로드 실패 메시지를 출력한다.

## 3.3.6 파일을 삭제한다.

1. 사용자 → 시스템 : 파일 삭제 요청
2. 시스템 → 사용자 : 삭제 확인 메시지 출력
3. 사용자 → 시스템 : 삭제 확인
4. 시스템 → 파일 DB : 파일 정보 조회 요청
5. 파일 DB → 시스템 : 파일 정보 반환
6. 시스템 → 파일 저장소 : 파일 삭제 요청
7. 파일 저장소 → 시스템 : 파일 삭제 성공 반환
8. 시스템 → 파일 DB : 파일 정보 삭제 요청
9. 파일 DB → 시스템 : 파일 정보 삭제 성공 반환
10. 시스템 → 사용자 : 삭제 성공 메시지 출력
11. 시스템 → 사용자 : 갱신된 파일 목록 출력

예외 흐름

- 사용자가 삭제를 취소하면 기존 화면을 유지한다.
- 파일 삭제 중 오류가 발생하면 삭제 실패 메시지를 출력한다.

## 3.3.7 폴더를 생성한다.

1. 사용자 → 시스템 : 폴더 생성 요청
2. 사용자 → 시스템 : 폴더 이름 입력
3. 시스템 → 폴더 DB : 폴더 이름 중복 확인 요청
4. 폴더 DB → 시스템 : 중복 확인 결과 반환
5. 시스템 → 폴더 DB : 폴더 정보 저장 요청
6. 폴더 DB → 시스템 : 저장 성공 반환
7. 시스템 → 사용자 : 폴더 생성 성공 메시지 출력
8. 시스템 → 사용자 : 갱신된 폴더 목록 출력

예외 흐름

- 동일한 폴더 이름이 있으면 중복 오류 메시지를 출력한다.

4. 파일 DB → 시스템 : 검색 결과 반환

예외 흐름

- 검색 결과가 없으면 “검색 결과가 없습니다.”라는 메시지를 출력한다.

3. 파일 DB → 시스템 : 파일 크기 정보 반환

5. 저장 용량 관리 → 시스템 : 계산 결과 반환
6. 시스템 → 사용자 : 저장 용량 정보 출력

예외 흐름

- 용량 계산 중 오류가 발생하면 용량 조회 실패 메시지를 출력한다.
- 저장 용량이 초과된 경우 업로드 제한 메시지를 출력한다.

## 3.3.10 사용자 계정을 관리한다.

1. 관리자 → 시스템 : 사용자 관리 메뉴 요청
2. 시스템 → 사용자 DB : 관리자 권한 확인 요청
3. 사용자 DB → 시스템 : 권한 확인 결과 반환
4. 시스템 → 사용자 DB : 전체 사용자 목록 조회 요청
5. 사용자 DB → 시스템 : 사용자 목록 반환
6. 시스템 → 관리자 : 사용자 목록 출력
7. 관리자 → 시스템 : 사용자 계정 상태 변경 요청
8. 시스템 → 사용자 DB : 사용자 계정 상태 변경
9. 사용자 DB → 시스템 : 변경 결과 반환
10. 시스템 → 관리자 : 변경 완료 메시지 출력

예외 흐름

- 관리자 권한이 없으면 접근 불가 메시지를 출력한다.
- 사용자 정보 조회 중 오류가 발생하면 조회 실패 메시지를 출력한다.

## 3.3.11 시스템 저장소 상태를 확인한다.

1. 관리자 → 시스템 : 저장소 관리 메뉴 요청
2. 시스템 → 사용자 DB : 관리자 권한 확인 요청

7. 저장 용량 관리 → 시스템 : 계산 결과 반환

# 5. 제약사항

## 5.1 기능 제약사항

1. 사용자는 로그인 후에만 파일 관리 기능을 사용할 수 있다.
2. 사용자는 본인이 업로드한 파일에만 접근할 수 있다.
3. 파일 업로드 시 허용된 파일 크기를 초과할 수 없다.
4. 파일 업로드 시 사용자의 남은 저장 용량을 초과할 수 없다.
5. 동일한 사용자 계정 내에서 같은 위치에 동일한 폴더 이름을 중복 생성할 수 없다.
6. 관리 기능은 관리자 권한을 가진 계정만 사용할 수 있다.

## 5.2 보안 제약사항

1. 비밀번호는 평문으로 저장하지 않고 해시 처리하여 저장해야 한다.
2. 로그인하지 않은 사용자는 파일 목록, 다운로드, 삭제 기능에 접근할 수 없어야 한다.
3. 사용자는 다른 사용자의 파일을 조회하거나 다운로드할 수 없어야 한다.
4. 서버에 저장되는 파일 경로는 외부에 직접 노출되지 않아야 한다.
5. 관리자 기능은 일반 사용자에게 노출되지 않아야 한다.

## 5.3 성능 제약사항

1. 파일 목록 조회는 일반적인 네트워크 환경에서 3초 이내에 응답하는 것을 목표로 한다.
2. 로그인 검증은 2초 이내에 처리되는 것을 목표로 한다.
3. 파일 검색은 3초 이내에 결과를 반환하는 것을 목표로 한다.
4. 파일 업로드 및 다운로드 시간은 파일 크기와 네트워크 상태에 따라 달라질 수 있다.

## 5.4 운영 제약사항

1. 시스템은 웹 브라우저 환경에서 동작해야 한다.
2. 데이터베이스와 파일 저장소는 안정적으로 연결되어야 한다.
3. 서버 장애 발생 시 파일 데이터 손실을 최소화할 수 있도록 관리되어야 한다.
4. 시스템 유지보수를 위해 사용자 정보와 파일 정보는 구조화하여 저장해야 한다.
