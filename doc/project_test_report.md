# 1. 서론

## 1.1 문서 목적 및 범위

본 문서의 목적은 Mini Drive 프로젝트에 대해 테스트 기준, 테스트 범위, 테스트 케이스, 예상 결과 및 테스트 결과를 정리하는 데에 있다.

Mini Drive는 웹 환경에서 사용자가 파일을 업로드, 다운로드, 관리, 검색, 공유할 수 있도록 지원하는 미니 클라우드 드라이브 시스템이다. 본 문서에서는 시스템의 내부 구현 구조를 알지 못한다는 가정하에 사용자의 관점에서 기능이 정상적으로 동작하는지 확인하는 블랙박스 테스트를 중심으로 테스트를 설계한다.

본 프로젝트는 실제 구현 및 테스트가 완전히 수행되지 않은 상황을 고려하여, 테스트 수행 결과뿐만 아니라 테스트 디자인 자체를 포함한다. 따라서 일부 항목은 실제 테스트 결과가 아닌 예상 결과 또는 테스트 설계 결과로 작성한다.

## 1.2 프로젝트 개요

Mini Drive는 개인 또는 팀 단위 사용자가 웹 브라우저를 통해 파일을 저장하고 관리할 수 있는 클라우드 파일 관리 시스템이다. 사용자는 회원가입 및 로그인 후 파일을 업로드하고, 폴더를 생성하여 파일을 분류하며, 필요한 파일을 검색하거나 다운로드할 수 있다. 또한 특정 사용자에게 파일을 공유하거나 권한을 설정하여 파일 접근을 제한할 수 있다.

주요 기능은 다음과 같다.

| 구분      | 주요 기능                          |
| ------- | ------------------------------ |
| 사용자 관리  | 회원가입, 로그인, 로그아웃, 계정 정보 관리      |
| 파일 관리   | 파일 업로드, 다운로드, 삭제, 파일 목록 조회     |
| 폴더 관리   | 폴더 생성, 폴더명 수정, 폴더 삭제, 파일 이동    |
| 검색 기능   | 파일명 기반 검색, 확장자 기반 검색           |
| 공유 기능   | 사용자 초대, 공유 링크 생성, 권한 설정        |
| 버전 관리   | 동일 파일 재업로드 시 버전 기록, 이전 버전 다운로드 |
| 저장공간 관리 | 사용자별 저장 용량 확인, 용량 초과 제한        |
| 보안 관리   | 로그인 여부 확인, 접근 권한 확인, 비인가 접근 차단 |
| 관리자 기능  | 사용자 계정 조회, 저장소 상태 확인           |

# 3. 테스트 케이스

## 3.1 테스트 케이스 선정

테스트 케이스는 Mini Drive의 주요 요구사항을 기준으로 선정하였다. 테스트는 시스템 내부 로직을 직접 확인하지 않고, 사용자가 웹 화면에서 입력을 수행했을 때 기대한 결과가 나타나는지를 확인하는 블랙박스 테스트 방식으로 설계하였다.

테스트 케이스는 다음 기준을 고려하여 선정하였다.

* 사용자가 가장 자주 수행하는 핵심 기능인지 여부
* 잘못된 입력이 발생할 가능성이 높은 기능인지 여부
* 보안 및 권한 문제가 발생할 수 있는 기능인지 여부
* 파일 데이터의 손실이나 접근 오류로 이어질 수 있는 기능인지 여부
* 실제 서비스 사용 흐름에서 반드시 확인되어야 하는 기능인지 여부

## 3.2 테스트 케이스 유형

본 프로젝트의 테스트 케이스 유형은 다음과 같다.

* 문자열 입력 테스트 케이스
  회원가입, 로그인, 검색, 폴더명 입력 등

* 파일 입력 테스트 케이스
  파일 업로드, 파일 형식 검증, 파일 용량 제한 등

* 동작 테스트 케이스
  다운로드, 삭제, 이동, 공유, 권한 변경 등

* 데이터 연동 테스트 케이스
  업로드된 파일이 목록에 반영되는지, 폴더 이동 후 위치가 변경되는지 확인

* 권한 및 보안 테스트 케이스
  로그인 여부, 사용자 권한, 공유 권한, 외부 링크 접근 확인

* 비기능 테스트 케이스
  브라우저 호환성, 응답 속도, 사용성, 오류 처리 확인

* T3은 비밀번호 길이 또는 형식 오류를 확인한다.
* T4는 필수 입력값 누락을 확인한다.
* T5는 중복 이메일 가입 제한을 확인한다.

```text
[Test Client - Web Browser]
          |
          v
[Mini Drive Web Application]
          |
          v
[Application Server]
          |
          +--------------------+
          |                    |
          v                    v
[Database Server]       [File Storage]
          |
          v
[Admin Page]
```

# 7. GitHub 리뷰 및 반영 내역

## 7.1 GitHub 업로드 내역

작성한 테스트 결과 보고서는 GitHub Repository의 다음 경로에 업로드한다.

```text
doc/test_report.md
```

추천 커밋 메시지는 다음과 같다.

```text
docs: add Mini Drive test report
```

또는

```text
docs: Mini Drive 테스트 결과 보고서 작성
```

## 7.2 조원 문서 리뷰 내역

본 과제에서는 같은 조에 속한 다른 팀원의 문서를 확인하고 GitHub Issue 또는 Pull Request를 통해 리뷰를 수행한다.

| 리뷰 대상 | 리뷰 방식        | 리뷰 내용                                   | 링크 |
| ----- | ------------ | --------------------------------------- | -- |
| 조원 A  | Issue        | 테스트 케이스에 예상 결과는 있으나 통과 기준이 부족하여 보완을 제안함 | #  |
| 조원 B  | Pull Request | 테스트 환경 설명이 부족하여 브라우저 및 DB 환경 추가를 제안함    | #  |
| 조원 C  | Issue        | 예외사항과 재개 조건이 명확하지 않아 표 형식으로 정리할 것을 제안함  | #  |

## 7.3 받은 리뷰 반영 내역

| 리뷰어  | 리뷰 내용                             | 반영 여부 | 반영 내용                               |
| ---- | --------------------------------- | ----- | ----------------------------------- |
| 조원 A | 파일 공유 기능 테스트 케이스가 부족함             | 반영    | 공유 링크, 권한 관리, 공유 해제 테스트 케이스 추가      |
| 조원 B | 실제 테스트가 없더라도 예상 결과와 설계 기준을 구분해야 함 | 반영    | 테스트 결과 장에 “예상 결과 및 테스트 설계 기준” 설명 추가 |
| 조원 C | 보안 테스트 항목이 더 필요함                  | 반영    | 비로그인 접근, URL 직접 접근, 세션 만료 테스트 추가    |

## 7.4 리뷰 반영 후 변경 사항 요약

리뷰 반영 전에는 파일 업로드, 다운로드, 로그인 등 기본 기능 위주의 테스트 케이스가 중심이었다. 리뷰 반영 후에는 Mini Drive의 핵심 특징인 공유 권한, 공유 링크, 버전 관리, 저장 용량, 보안 접근 제어 관련 테스트 케이스를 추가하였다. 이를 통해 단순 파일 관리 시스템이 아니라 웹 기반 클라우드 파일 공유 시스템으로서의 품질을 더 구체적으로 검증할 수 있도록 문서를 보완하였다.
